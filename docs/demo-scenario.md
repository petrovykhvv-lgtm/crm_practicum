# Демонстрационный сценарий

Цель: за 10–15 минут пройти путь менеджера и убедиться, что все связи и показатели работают. Тот же сценарий автоматически проверяет `tests/integration/scenario.test.ts`.

## 0. Подготовка контрольных данных

```bash
npm install && cp .env.example .env
npm run db:up && npm run db:deploy      # или свой PostgreSQL, см. README
npm run db:seed                          # в консоли: «Seed: база «…»», затем счётчики
npm run dev                              # http://localhost:3000
```

Ожидаемые данные после seed (проверяются самим seed и тестом `seed.test.ts`):

| Сущность | Количество | Примечание |
|---|---|---|
| Лиды | 6 | источники site ×2, phone, email, manual, referral |
| Компании / контакты | 4 / 5 | |
| Сделки | 6 | по одной на стадию |
| Активности | 8 | 2 заметки, 6 задач (2 просрочены, 2 на сегодня) |
| Менеджеры / причины отказа | 3 / 6 | |

Ожидаемый дашборд сразу после seed (период 90 дней): всего лидов 6, открытых сделок 4, просроченных задач 2, выиграно 1 (3 900 000 ₽), в блоке «Сделки, требующие внимания» две сделки (MosBuild и Pop-up).

Чтобы начать с чистого листа, `npm run db:reset`.

## 1. Запуск и интерфейс

1. Откройте `/`: шапка с логотипом, меню, «+ Создать», поиск, «Работаю как», шестерёнка настроек. Дашборд показывает KPI, воронку продаж, динамику по этапам, сводки, «Новые лиды», «Сделки, требующие внимания», «Почему теряем сделки».
2. В «Работаю как» выберите «Анна Мельникова»: теперь она подставляется ответственной по умолчанию.

## 2. Лид

1. «Лиды» → «Создать лида». Нажмите «Создать лида» с пустой формой: у полей «Имя» и «Источник» появятся ошибки, фокус перейдёт на первое.
2. Введите имя «Анна Тестова», источник «Сайт», email `LEBEDEVA@techno-m.example` (он есть в seed), компанию «Техно-М»: форма покажет **возможные дубли** (лид, контакт, компания). Замените email на `testova@newclient.example`, компанию на «Новый Клиент», бюджет 1 200 000.
3. После создания открылась карточка: ответственный «Анна Мельникова», блок «Конвертация», в «Истории изменений» запись «Создан лид».
4. В списке «Лиды» найдите её через поиск (`тестова`), отфильтруйте по источнику «Сайт», отсортируйте по бюджету, нажмите «Экспорт CSV».

## 3. Конвертация (`convert lead`)

1. В карточке лида «Конвертировать»: форма предзаполнена (контакт, компания «Новый Клиент», сделка с суммой из бюджета).
2. Нажмите «Конвертировать лида». Лид получил статус «Конвертирован», блок «Результат конвертации» содержит ссылки на компанию, контакт и сделку.
3. Откройте их: у компании в карточке контакт и сделка, у контакта компания и сделка, у сделки «Исходный лид». Конвертировать повторно нельзя (блока «Конвертация» нет, страница `/leads/{id}/convert` объясняет причину).

## 4. Активность

1. В карточке сделки: заметка «Клиент просит два варианта планировки», затем задача «Уточнить размеры площадки» со сроком позавчера (исполнитель по умолчанию Анна).
2. Задача помечена «просрочена». «Задачи» → «Просрочено» показывает её, в меню у «Задач» счётчик вырос.
3. Отметьте задачу выполненной, нажмите «Изменить» (смените текст), затем «Удалить» (окно подтверждения с последствиями). Журнал карточки фиксирует каждое действие.

## 5. Воронка

1. «Воронка»: в «Новой» карточка «Новый Клиент». Перетащите её в «Квалификацию»: внизу появится «Отменить» (10 секунд), нажмите его, карточка вернётся.
2. Перетащите по цепочке до «Согласования». Откройте карточку сделки: стадия та же. В журнале записи «Стадия: …».
3. Правила: в «Выиграна» сделка без суммы или контакта не переходит (сообщение, карточка возвращается). Перетащите «Новый Клиент» в «Проиграна»: окно причины. Для «Другое» без комментария кнопка неактивна. После подтверждения сделка в «Проиграна», причина видна в карточке.
4. Из «Проиграна» перетащите сделку на открытую стадию: причина и дата закрытия очищаются.

## 6. Дашборд

1. Откройте `/` заново: лидов 7, просроченных задач учитывает новую, воронка и «Почему теряем сделки» показывают отказ с причиной «Другое».
2. Измените сумму сделки (редактирование) и откройте дашборд снова: суммы и прогноз обновились (реального времени нет, данные считаются при каждом открытии).
3. Выберите период «7 дней», шаг «по дням», фильтр «Ответственный: Анна»: показатели пересчитываются, в шапке дашборда указан фильтр.

## 7. Дополнительно

- **Импорт:** «Лиды» → «Импорт CSV»: скачайте шаблон, добавьте строки, загрузите с флажком «Только проверить», затем без флажка. Строки с ошибками и дубли пропускаются с указанием номера строки.
- **Настройки** `/settings`: добавьте менеджера, причину отказа, измените вероятность стадии (прогноз на дашборде пересчитается).
- **Телефон:** в окне 390 px шапка фиксирована и компактна, в списках остаются главные колонки.

## Критерии успеха

Все шаги выполняются без ручной правки кода и без прямого обращения к базе данных, ошибки показываются пользователю, связи в карточках согласованы, дашборд меняется после правок.
